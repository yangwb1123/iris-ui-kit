## Design decisions (documented in code + comparison doc)

- **Direction per baseline**: `diffRows(liveData, compareWith, rowKey)` — live rows absent from the snapshot render `data-iris-row-removed`, rows in both with differing cells render `data-iris-row-changed` (+`data-iris-cell-changed` + tooltip), and the tooltip shows live value → snapshot value (`旧值: X → 新值: Y`). Snapshot-only rows are `added` in the core diff but have **no rendered slot** — the compare view renders the live dataset (documented).
- **`Object.is` semantics** (≠ batch-AT `!==`): NaN≡NaN (no change), +0≠−0 (change) — value identity for a compare view.
- **Compare tooltip wins** over tooltipConfig on changed cells; tooltipConfig still applies to unchanged cells (documented override).
- **Tokens**: changed → `--iris-surface-selected`; added/removed → success/danger tints via `color-mix` over `--iris-background` (no magic rgba; engines without color-mix fall back to the inherited row background — documented).
- **Formula columns** are computed display values — their own cell diffs are not flagged (the referenced field cells are); documented simplification.
- **Complexity budget**: the cell-render arrow stays at its pre-change complexity via extracted helpers (`cellChangeOf`/`compareCellAttr`/`cellTitle`), mirroring the `dirtyCellState` pattern.
