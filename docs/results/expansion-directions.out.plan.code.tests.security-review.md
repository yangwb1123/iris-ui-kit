## Finding #1 — No Plugin Sandboxing / Capability Model

| Field           | Value                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                         |
| --------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Category        | Threat Model                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                  |
| Severity        | **Critical**                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                  |
| Title           | Plugins have unrestricted access to the entire registry (no privilege separation)                                                                                                                                                                                                                                                                                                                                                                                                                                                             |
| Location        | `plugin.ts:32-54` — `PluginRegistry` interface, `plugin.ts:124-153` — registry implementation                                                                                                                                                                                                                                                                                                                                                                                                                                                 |
| Description     | Every plugin receives a full `PluginRegistry` object that grants access to **all four** registration surfaces (tokens, messages, stores, teardowns). There is no opt-in permission system, capability scoping, or isolation boundary. A plugin that registers a store key collision can **override** another plugin's store (last-wins). A compromised or malicious plugin can read/write any registered token, poison any i18n message, replace any store, and inject teardown handlers that execute on provider unmount.                    |
| Attack Scenario | 1. Attacker publishes a malicious third-party plugin named `"auth-helper"` that registers `store('auth')` → replaces the legitimate auth store with one that exfiltrates tokens. Any component calling `usePluginStore('auth')` receives the poisoned store. 2. Attacker registers `'--iris-button-bg'` → a CSS value that references a malicious URL via `var(--iris-malicious)` which a compromised theme provider might evaluate. 3. An `onTeardown` callback could data-exfiltrate during unmount (e.g., `navigator.sendBeacon` to a C2). |
| Impact          | Full compromise of any data flowing through plugin stores; ability to manipulate UI rendering via token/message poisoning; persistent exfiltration via teardown hooks. In a multi-tenant or plugin-ecosystem scenario (e.g., third-party plugins from a registry), this is a supply-chain critical vulnerability.                                                                                                                                                                                                                             |
| Recommendation  | Introduce a capability-based permission model. At minimum: (a) separate `PluginRegistry` into focused sub-interfaces (`TokenRegistrar`, `MessageRegistrar`, `StoreRegistrar`, `TeardownRegistrar`) so plugins opt into what they need; (b) consider an `IrisPlugin.permissions` array that the provider validates against a host-defined allowlist. For the immediate term, audit all first-party plugins and ensure they follow least-privilege (the existing plugins do).                                                                   |
| Effort          | L (structural change)                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                         |

## Finding #2 — `destroy()` Lifecycle Dead Code in All Four Adapters

| Field           | Value                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                |
| --------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Category        | Threat Model                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                         |
| Severity        | **High**                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                             |
| Title           | `IrisPlugin.destroy()` is never called by any adapter — lifecycle contract is broken                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                 |
| Location        | `plugin.ts:89-97` — `destroy()` definition; `plugin.ts:230-249` — `reloadPlugins()` (the only caller); React: `IrisProvider.tsx:60` — `useEffect` calls `teardown()` only; Vue: `IrisProvider.ts:77`; Solid: `IrisProvider.tsx:55`; Svelte: `IrisProvider.svelte:40`                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                 |
| Description     | The `IrisPlugin` interface defines a `destroy()` lifecycle method intended for cleanup when a plugin is dynamically removed (e.g., hot-reload, feature toggling). However, **none of the four framework adapters call `reloadPlugins`**. They all just call `runPlugins` in a memo/derived and rely on the returned `teardown()` for cleanup. The exported `reloadPlugins()` function is the only code path that invokes `destroy()` — and it's never consumed by the adapters. This means: (a) `destroy()` is a false contract; (b) plugins that rely on `destroy()` for critical cleanup (closing WebSockets, flushing caches, revoking object URLs) will leak resources when dynamically toggled; (c) if a security-sensitive plugin needs to revoke access on removal, it cannot reliably do so. |
| Attack Scenario | A security plugin registers a store containing decryption keys. When the plugin is removed at runtime (plugins prop changed), `destroy()` never runs; the keys remain in memory and may be accessible via `usePluginStore('security')` if the new plugin set doesn't register a conflicting key.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                     |
| Impact          | Resource leaks; inability to reliably revoke plugin access at runtime; false sense of security from the documented `destroy()` hook.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                 |
| Recommendation  | Update all four `IrisProvider` adapters to use `reloadPlugins` when the `plugins` prop changes (instead of `runPlugins`). This ensures `destroy()` is called on removed plugins. Alternatively, if `destroy()` is not intended for dynamic removal (just provider teardown), remove it from the interface to prevent false expectations.                                                                                                                                                                                                                                                                                                                                                                                                                                                             |
| Effort          | M (coordinated change across 4 adapters + tests)                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                     |

## Finding #3 — `devWarn` in Production Leaks Sensitive System Information

| Field           | Value                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                             |
| --------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Category        | Data Protection                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                   |
| Severity        | **Medium**                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                        |
| Title           | `devWarn` guard may fail in certain production environments, leaking plugin names, store keys, and token names                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                    |
| Location        | `plugin.ts:106-110` — `devWarn()` function                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                        |
| Description     | The `devWarn` function is supposed to be silent in production by checking `process.env.NODE_ENV === 'production'`. However, the guard is: `typeof process !== 'undefined' && process.env && process.env.NODE_ENV === 'production'`. This has two failure modes: (a) In bundlers where `process.env.NODE_ENV` is string-replaced but `process` is still globally available, if the replacement is imperfect (e.g., `process.env['NODE_ENV']` instead of `process.env.NODE_ENV`), the guard evaluates `undefined === 'production'` → `false` → warnings fire in production. (b) In Deno or other runtimes where `process` exists but `process.env` is a Proxy without the expected shape, the guard could short-circuit incorrectly. Even though this is "just" a warning, the messages disclose: plugin names (`plugin "x" installed more than once`), store keys (`store "x" registered by multiple plugins`), token names, and dependency graph structure — all of which aid an attacker in fingerprinting the plugin landscape. |
| Attack Scenario | An attacker who can trigger warnings (e.g., via reflective XSS that calls `console.warn` or by observing browser DevTools console) learns about the internal plugin architecture, store keys, and token names used by the application, enabling more targeted store-collision or token-override attacks.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                          |
| Impact          | Information disclosure aiding plugin-system reconnaissance.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                       |
| Recommendation  | Tighten the production guard: replace with a bundler-replaceable constant (e.g., `process.env.NODE_ENV` with a tsup `define`). Better: use an explicit `__DEV__` or `__IRIS_DEV__` flag set at build time that is `false` in production bundles. Alternatively, remove the production check entirely and gate all `console.warn` calls behind a single conditional that tsup can dead-code-eliminate in production builds.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                        |
| Effort          | S                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                 |

| Category        | Input Validation                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                    |
| Severity        | **Medium**                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                          |
| Title           | Plugin identifier strings (name, store keys, token keys) are not sanitized                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                          |
| Location        | `plugin.ts:116-119` — `createPlugin` name validation (only checks empty string); `plugin.ts:131-142` — `registerStore`/`registerLazyStore`; `plugin.ts:124-128` — `registerTokens`                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                  |
| Description     | Plugin names, store keys, and token CSS variable names are used in `devWarn` messages without sanitization. A plugin with a name like `"'; alert('xss'); //"` would be interpolated directly into a `console.warn` call (though `console.warn` itself doesn't evaluate HTML, so this is limited to console pollution). (c) Validate token CSS var names match `/^--[a-zA-Z0-9_-]+$/` in `registerTokens` and wrap each `setProperty` in try/catch so one invalid name doesn't block others.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                              |

## Finding #5 — Eager Store Factory Invocation Enables DoS via Throwing Factory

| Field           | Value                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                   |
| --------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Category        | Threat Model (Denial of Service)                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                        |
| Severity        | **Medium**                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                              |
| Title           | A throwing store factory blocks subsequent plugin installations                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                         |
| Location        | `plugin.ts:142` — `stores.set(key, factory())` in `registerStore`; `plugin.ts:161-175` — plugin install loop                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                            |
| Description     | The `registerStore` method eagerly invokes `factory()` during `runPlugins`. If any plugin's store factory throws synchronously, the exception propagates up through `runPlugins` uncaught, preventing all **remaining** plugins (in install order) from being installed. The plugin install loop at line 161-175 is not wrapped in a try/catch per plugin. The test suite validates that a throwing teardown does not block other teardowns (line 167-179 in test) but there is **no similar isolation for throwing installs**. Similarly, `registerLazyStore` defers the factory (so a lazy store cannot cause install-time DoS), but once materialized, a throwing lazy store factory would propagate to the first `get()` caller via the adapter's `usePluginStore`. |
| Attack Scenario | Plugin A (malicious, installed first in array order) registers a store whose factory throws → `runPlugins` throws → Plugin B through Plugin N never get installed → `IrisProvider` crashes → application fails to render. Alternatively, a compromised dependency of a legitimate plugin could cause the same effect.                                                                                                                                                                                                                                                                                                                                                                                                                                                   |
| Impact          | Denial of service: entire IrisProvider tree fails to mount.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                             |
| Recommendation  | Wrap each plugin's `install()` call in try/catch in the main install loop (around `plugin.ts:172`). If an install throws, emit a `devWarn` and continue to the next plugin. Also wrap eager `factory()` invocations in try/catch: on throw, set a sentinel value or re-throw after continuing. This mirrors the already-implemented teardown isolation pattern.                                                                                                                                                                                                                                                                                                                                                                                                         |
| Effort          | S                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                       |

## Finding #6 — CSS Token Values Not Sanitized (Low-Risk)

| Field           | Value                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                           |
| --------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Category        | Input Validation                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                |
| Severity        | **Low**                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                         |
| Title           | Plugin token values are applied as-is to `style.setProperty`, could cause visual corruption                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                     |
| Location        | `plugin.ts:124-128` → `applyCssVars.ts:26`                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                      |
| Description     | Token values from plugins are written directly via `target.style.setProperty(name, value)`. While CSS custom property values are generally safe (they're parsed as CSS values, not executed), certain edge cases exist: (a) a value containing `!important` would be treated as part of the custom property value (not applied specially) — this is safe but confusing. (b) A value containing `url()` with a `javascript:` scheme would not execute because CSS custom properties in `var()` references are substituted before URL resolution — the browser's CSS parser handles this safely. (c) Very long values (>1MB) could cause memory pressure on the style system. The primary risk is visual: a malicious token value like `"red; background-image: url('http://evil.com/steal')"` would set `--iris-x` to the entire string (including the semicolon) because CSS custom properties capture the entire value up to the closing `}`, but inline `style.setProperty` only sets one declaration — so the semicolon is part of the value, not a separator. The browser's CSS parser handles this safely. |
| Attack Scenario | Limited to visual corruption of the UI. A token value containing unexpected characters could cause CSS cascading issues if the value is then used in a `var(--iris-x)` reference in a context where it's interpolated unsafely (e.g., in a `style` attribute via JS). However, the core system only applies tokens as CSS custom properties and doesn't use them in inline `style` attributes unsafely.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                         |
| Impact          | Minor: visual corruption; potential information disclosure if token values reflect user data (unlikely in current usage).                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                       |
| Recommendation  | Document that token values should not contain untrusted user input. Consider adding a size cap (e.g., 10KB per value) to prevent memory-pressure DoS. For defense-in-depth, consider validating values against a pattern like `/^[^;{}]+$/` to catch obvious injection attempts.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                |
| Effort          | S                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                               |

## Finding #10 — No Depth Limit on Plugin Dependency Resolution

| Field           | Value                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                              |
| --------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| Category        | Threat Model (Denial of Service)                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                   |
| Severity        | **Low**                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                            |
| Title           | `orderPlugins` recursive DFS has no depth limit — stack overflow on crafted dependency chain                                                                                                                                                                                                                                                                                                                                                                                                                                                                       |
| Location        | `plugin.ts:189-207` — `orderPlugins` with recursive `visit()`                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                      |
| Description     | The topological sort in `orderPlugins` uses recursion without a maximum depth. A crafted dependency chain of ~10,000 plugins (each depending on the next) would cause a stack overflow in V8 (~12k frame limit) or other engines. While requiring 10k plugins is unrealistic in practice, a deeply nested dependency tree (e.g., plugin A → B → C → ... → Z → ... → 10000) could be constructed maliciously to crash the provider on mount. The `onStack` cycle detection prevents infinite recursion for cycles but does not limit the depth of an acyclic chain. |
| Attack Scenario | A plugin with `dependsOn: ['b']`, plugin b with `dependsOn: ['c']`, etc., forming a chain of ~15k+ entries, submitted as a single array. When `orderPlugins` recursively visits the chain, the call stack overflows and `runPlugins` throws, crashing the IrisProvider.                                                                                                                                                                                                                                                                                            |
| Impact          | Denial of service via stack overflow.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                              |
| Recommendation  | Replace the recursive DFS with an iterative topological sort (Kahn's algorithm) that has no stack depth issue. Alternatively, add an explicit depth counter (e.g., `if (depth > 1000) throw new Error(...)`) to the recursive approach.                                                                                                                                                                                                                                                                                                                            |
| Effort          | M (rewriting the sort) or S (adding depth guard)                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                   |

## STRIDE Analysis Summary

| Category                   | Assessment                                                                                                                                                                                                                                              |
| -------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **Spoofing**               | **Low risk.** Plugin identity is name-based, not cryptographic. No authentication of plugin source. A malicious plugin can impersonate another by using the same name (Finding #1, #9).                                                                 |
| **Tampering**              | **Medium risk.** Plugin stores use last-wins collision semantics. Any plugin can overwrite any store (Finding #1). Messages are shallow-merged. Tokens overwrite with devWarn only. No integrity verification of plugin content.                        |
| **Repudiation**            | **Low risk.** Plugin system doesn't log actions. Console warnings are the only audit trail. No non-repudiation mechanism exists, but this is expected for a UI library.                                                                                 |
| **Information Disclosure** | **Medium risk.** `devWarn` leaks internal structure (Finding #3). Plugin stores with sensitive data (auth tokens, user data) could be accessed by any plugin via store-key collision (Finding #1). `proTableLabel` output must be escaped (Finding #8). |
| **Denial of Service**      | **Medium risk.** A throwing store factory blocks all subsequent plugins (Finding #5). Deep dependency chain causes stack overflow (Finding #10). Unvalidated token names could throw on `setProperty` (Finding #4).                                     |
| **Elevation of Privilege** | **Medium risk.** No capability model — all plugins have equal access to all registry surfaces (Finding #1). A plugin with store-write access can replace authentication/authorization stores.                                                           |

## Final Summary

### Overall Security Posture: **Needs Improvement**

The plugin system is well-architected at a high level (clean separation of concerns, proper isolation of teardowns, SSR-safe, framework-agnostic) but has **structural security gaps** that would become critical if the ecosystem were to support third-party plugins.

### Top 3 Critical Issues

1. **No plugin sandboxing (Finding #1)** — Any plugin has full access to all registry surfaces. In a third-party plugin ecosystem, this is a critical supply-chain vulnerability. Stores that hold authentication tokens, user data, or cryptographic keys can be overwritten or read by any plugin.

2. **`destroy()` lifecycle broken (Finding #2)** — The `destroy()` hook is dead code in all four adapters. Plugins that need to revoke security-sensitive resources (e.g., auth sessions, encryption keys) on removal cannot do so reliably. This creates a false sense of security around dynamic plugin lifecycle management.

3. **Production warning leakage (Finding #3)** — `devWarn` may fire in production environments, leaking plugin architecture details (names, store keys, token names, dependency graph) to console observers.

### Top 3 Quick Wins

| Finding                                  | Fix                                                                                                             | Effort      |
| ---------------------------------------- | --------------------------------------------------------------------------------------------------------------- | ----------- |
| **#4** — Input validation on identifiers | Add regex validation for plugin names, store keys, and token keys in `createPlugin` and registry methods        | **< 1 day** |
| **#5** — Throwing install isolation      | Wrap each plugin `install()` and eager `factory()` in try/catch (mirroring existing teardown isolation pattern) | **< 1 day** |
| **#10** — Depth guard on dependency sort | Add a depth counter (e.g., 1000) to the recursive topological sort                                              | **< 1 day** |

### Security Debt

1. **Plugin capability model** — Requires a cross-cutting API design change to introduce scoped registries. Track as a v2 roadmap item.
2. **Adapter lifecycle alignment** — Fixing `destroy()` requires changes across all four adapter providers and tests. Medium effort (1-3 days).
3. **`reloadPlugins` adapter integration** — Currently unused by all adapters. Should be adopted to properly handle dynamic plugin changes.
4. **CI plugin security scan** — No automated scanning for plugin behaviors (e.g., store collisions, token overrides, network exfiltration in teardowns).
5. **Size budget maintenance** — As noted in AGENTS.md, `@iris-ui/core` is 10KB gzipped. A capability model with per-plugin permission manifests should be designed to minimize bundle impact.
