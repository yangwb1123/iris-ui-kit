**1. Undo** — core `createUndoStack<Row[]>` created once in a ref (`maxHistory: 100`, `initial: [...data]`, `equals: sameRowList` — same length + row-reference equality skips dead no-op steps). **Flagged correction to the task wording**: the task said "push the PRE-change row list", but the core stack convention is POST-change states — `undo()` returns the state before the last mutation, `redo()` the state after it (verified against `core/undo.test.ts` and the sibling `useTableUndo.ts`, which pushes the current data on `pushSnapshot()`). Pushing pre-change makes `Ctrl+Y reapplies` fail from the SECOND mutation onward (redo() would return the same pre-change snapshot again); the explicit "Ctrl+Y reapplies" test forced the post-change design. **Two mutation funnels wired, not one**: `commitRowList` (row ops / paste / fnr / range clear / batch edit / loadData) passes its `next`; `commitValue` (cell/row edits write back through `setLiveData` directly and never reach `commitRowList`) computes the post-change list via `setCellValue` and eagerly syncs `externalDataRef` so a same-event multi-commit (row-mode `switchRowEdit`) snapshots the true intermediate states (React defers updaters — without the eager sync every snapshot in one event would capture the same stale list). undo/redo replay through `applyUndoSnapshot` with a `restoringRef` guard so the replay's `commitRowList` never re-pushes; replay fires `onDataChange` exactly once per step. Selection: vanished keys are pruned via one `selModel.set` after rebase (survivors keep their selected state). Keyboard: window keydown gated on `undo`, root-contained targets only, skips INPUT/TEXTAREA/SELECT/`data-iris-table-editor`, and returns early while `editingTarget !== null || rowEditing !== null` (the editor's own Ctrl+Z wins). Toolbar: ↶/↷ glyph buttons after the title (`data-iris-table-undo`/`data-iris-table-redo`), `disabled` from `canUndo()/canRedo()` re-read on every render (tick state bumps on each push/undo/redo — the stack is a plain controller, not an observable store). External re-feeds re-baseline the stack only while untouched (interaction-scoped, vxe undoRedoHistory parity).

**2. Batch edit panel** — `toolbar.batch.edit: true` turns the existing batch button (multi + selection ≥ 1) into the built-in panel: editable-column `<select>` (same `c.editable` gating as inline editing) + value input + 应用 (`data-iris-batch-edit-apply`, `table.batchEdit.apply`). Apply = ONE `commitRowList` writing the value into every selected row (addressed by the `rowKey` field; strings stay strings, editRules not re-validated — paste parity); selection unchanged; exactly one `onDataChange`; the mutation is itself undoable (Ctrl+Z reverts it). Panel closes on apply / Escape / outside pointer-down (trigger button excluded — clicking it toggles). `edit: false`/absent keeps the external `onClick` byte-identical.
