# vxe-grid 功能清单 vs iris-ui 现状与构建路线

> 来源：vxe-table@4.20.10 / vxe-pc-ui@4.16.27 类型定义与文档（2026-08 提取）
> 目标：用 iris-ui 逐步构建同等功能的可编辑 Table（四框架），并实现组合接口。

## 最终覆盖总结（2026-08-11，react）

**vxe-grid 功能面全部移植完成（react，批 W 收官）**：`tableProps` ~90 项 + 表格方法（handle）+ 事件 + grid 特有 `layouts`/`zoomConfig`/`visibleMethod` 全部对齐（react）。`customConfig`（列自定义面板，批 S）：工具栏 `columnSettings` 按钮打开完整面板（搜索 + 拖拽排序 + 可见性切换 + 重置），确认后经 `columnOrder`/`onColumnOrderChange` 受控提交，分组表仅作用于顶层列。`zoomConfig`（批 U）：工具栏 ⛶/✕ 切换 + fixed 覆盖层 + Esc 退出，缩放时工具栏提升至覆盖层之上（✕ 退出可达）；`layouts`：form/toolbar/pager 各节 `hidden` 抑制；`visibleMethod`：列可见谓词（与 columnVisibility AND，谓词 veto 优先）。`loadData`/`reloadData`/`commitProxy`/`getProxyInfo`（批 V）：代理方法对齐（loadData 走 liveData 写回通道，代理 state 总数在下次 query 前不变——core remote source 无 setData，文档化）；`onEditStart`/`onEditClosed`（批 V，cell 模式）+ `onScroll`（批 V）+ `onSelectAllChange`（批 V 增量——vxe 无此 emit）。`getFilteredData`（批 W）：当前筛选+排序视图快照副本；`exportCurrentViewCsv`（批 W）：导出当前视图（筛选/隐藏列/分组叶列均正确，ref 镜像最新态）；`showHeaderOverflow`/`showFooterOverflow`（批 W）：表头/表尾溢出省略号开关（默认保持，false → wrap + visible，body 不受影响）。

**vue 对齐（批 X）**：`proxyConfig`（服务端数据源：remoteSort/remoteFilter/分页/autoLoad/编辑回写）、`formConfig`（搜索表单：草稿/应用双态、代理合并 filters、本地过滤）、`multiSort`（多列排序：点击追加/原地升→降/移除 + 代理 `sorts`）、工具栏扩展（代理生命周期/状态/pager/写回）四块与 react **同名同语义**，共用 core 同一控制器；SSR 安全（首查 `onMounted` 触发，`renderToString` 不发请求）、受控 `sort`/`multiSortState` 变更推送代理、代理模式本地过滤仅 `filters` prop（React 对齐）。

**vue 对齐（批 Y）**：`columnVisibility`（+ `update:columnVisibility` emit）、`filters` 文本筛选（substring 大小写不敏感忽略空值，与 formConfig AND，远程代理合并 filters）、`seq`/`seqStartIndex` 序号列、`spanMethod` 合并单元格（resolveSpan + 占用集，被覆盖格跳过）、`columnDrag` 列拖拽（core createSortable 桥，分组表头不支持——文档化）、`rowDrag` 行拖拽（代理 liveData / 本地 override 重排 + `onDataChange`/`onReorder`）、`expose` 代理方法（`loadData`/`reloadData`/`commitProxy`/`getProxyInfo`）。

**vue 对齐（批 Z）**：`editConfig.mode='row'` 行编辑模式（会话 `Map<cellId,{draft,error}>` + 共享提交核心，cell 模式字节一致；点击整行开编辑、逐列 Enter/blur 提交、Escape 整行取消、行切换先提交、同步校验失败阻断切换、异步校验后取消丢弃提交）、`contextMenu` 右键菜单（虚拟光标锚点 + Teleport body，Esc/外部/滚动关闭，禁用项 inert，表头/序号/选择/汇总格排除）、`filterValues` 筛选面板（checkbox 面板 + OR 匹配通道与文本 filters AND，远程代理逗号合并）、树形 `lazyLoad` 懒加载（lazyChildrenOf 优先于 getSubRows，epoch 防陈旧回填）。**均 additive、core 零改动**（review 修复：初始代理 params 的 filters 逗号合并改按 `remoteFilter` 门控并合并文本 filters，React 对齐）。其余 react-only 能力（批 2/5/J–W 剩余）为 **vue/solid 剩余缺口**，**svelte 核心批 AC 已交付、交互批 AD 为下一轮**（见构建状态表下方）。

**solid 对齐（批 AA，核心批）**：`columnVisibility` 列显隐（`displayColumns` 驱动扁平/分组表头、body、summary、gridTemplate 全部渲染路径，引用保持）、`filters` 文本筛选（substring 大小写不敏感忽略空值、`filterMethod` 覆盖、与 formConfig AND、远程代理合并）、`seq`/`seqStartIndex`/`seqMethod` 序号列（含 `proxyConfig.seq` 代理累计序号）、`spanMethod` 合并单元格（每趟占用集，键控 bodyEntries 引用 + 方法身份重建，gridColumnEnd span n + rowspan 覆盖格跳过）、`proxyConfig` 服务端数据源（remoteSort/remoteFilter/分页/autoLoad/编辑回写/累计序号 + `pagerConfig` pageSizes/showTotal + solid `IrisPagination`，presence-keyed 生命周期 + SSR 安全 + 去重防双请求）、`multiSort` 多列排序（点击追加/原地升→降/移除 + 链式比较器 + 序号徽标 + 受控/非受控 + 代理 `sorts`）、`formConfig` 搜索表单（草稿/应用双态、提交→`{filters, page:1}`、重置 noop 重查）、工具栏扩展（refresh 代理重查/export/buttons/batch-with-keys）八块与 react/vue **同名同语义**，共用 core 同一控制器；SSR 安全、**core 零改动、纯 additive**（review 修复：spanMethod 占用集按方法身份键控重建——换函数不换数据时被覆盖格恢复；manifest 提取器对多行 spanMethod 签名的解析 artifact，solid props 改 react 同款内联对象形）。**solid 对齐（批 AB，交互批）**：`rowDrag` 行拖拽（core createSortable 桥：4px 阈值 → rects 一次收集 → closestCenter → 重排，tap 无位移取消 + 释放清理，本地 override + `onDataChange`/`onReorder` 双通道）、`columnDrag` 列拖拽（分组表头仅叶列）、`editConfig.mode='row'` 行编辑模式（整行开编辑、逐列 Enter/blur 提交、Escape 整行取消、行切换先提交、同步校验失败阻断、Tab 逐列提交导航；会话 epoch 守卫——异步校验 pending 中 Escape 取消不写回、双击 Enter 单次提交）、`contextMenu` 右键菜单（虚拟光标锚点 + portal，Esc/外部/滚动关闭，禁用项 inert，表头排除）、`filterValues` 筛选面板（触发不开排序 + checkbox OR 匹配与文本 filters AND + 远程代理逗号合并 + core i18n 键）、代理方法（`loadData`/`reloadData`/`commitProxy`/`getProxyInfo` + `clearSort`/`clearFilter`；loadData 本地 override 在下一次查询结果 ref 变化时整页替换——分页切换无陈旧行）。**均 additive、core 零改动**（review 修复：异步提交 epoch 守卫对齐 core sessionGen、代理 loadData 页切换替换、rowMode 优先于 cellRange 点击、同行双击重开整行；gate 修复：行编辑内联编辑器模板 SSR 水合对齐）。其余 react-only 能力同 vue 剩余缺口（见构建状态表下方）。

**svelte 对齐（批 AC，核心批）**：`columnVisibility` 列显隐（`displayColumns`/`leafColumns` 驱动扁平/分组表头、body、summary、gridTemplate 全部渲染路径，`!== false` 语义与 react 一致，挂载后隐藏/恢复反应式生效）、`filters` 文本筛选（substring 大小写不敏感忽略空值、`filterMethod` 覆盖、与 formConfig AND、远程代理合并，`{name:''}` 不重查）、`seq`/`seqStartIndex` 序号列（含 `proxyConfig.seq` 代理累计序号）、`spanMethod` 合并单元格（`buildSpanPlan` 占用集纯计划——跨虚拟窗口正确，与 react 渲染期 ref 同语义）、`proxyConfig` 服务端数据源（presence-keyed `$effect` 控制器生命周期——内联身份不重建、absent/卸载销毁；remoteSort/remoteFilter/分页/autoLoad/编辑回写 + 互斥 sort/sorts 通道 + pager = svelte `IrisPagination`）、`multiSort` 多列排序（点击追加/原地升→降/移除 + 链式比较器 + 徽标 + aria-sort + 代理 `sorts`，受控父拒绝无乐观翻转）、`formConfig` 搜索表单（草稿/应用双态、签名键控重播种、提交→合并 filters + 页 1、重置 noop 重查）、工具栏扩展（title/refresh/export/buttons/batch-with-keys）八块与 react/vue/solid **同名同语义**，共用 core 同一控制器；**core 零改动、纯 additive、零硬编码 hex**（review：`onColumnVisibilityChange` 事件为契约内延后——react 亦仅设置面板触发；`grouped` 由 `displayColumns` 计算与 solid/vue 一致）。**svelte 交互批 AD 为下一轮**。

**批 AE（虚拟树 + 四框架 example）**：react 虚拟树/详情行修复——`virtualScroll` 门控放开（原 flat+detail / tree / tree+detail × virtual 组合丢详情行），`BodyPlanEntry.kind='detail'` 每展开行一个详情槽（内容超高时槽内滚动，源码+设计文档已注明），展开/收缩经 `expandedKeys → plan → items.length` 全链路重钳制（layout effect 预绘同步 scrollTop，无空白帧，外部折叠深滚动时 DOM+state 双重钳制）；新增 `virtual-tree.test.tsx` 5 测试（flat 不变 / 树窗口化 / 展开增 itemCount 保滚动 / 外部折叠重钳制 / tree+detail 组合）+ 更新 2 处旧 pin。**四框架 example**：vue/solid/svelte CMS 各新增 `VxeGridExamplePage`（5 节镜像 react：basic / 行编辑 / 服务端代理 / 搜索表单 / 行操作，`checkMethod`/`tableRef.insertRow` 为 react-only 已 grep 验证，行操作走本地响应式 state）+ 菜单 `vxe-example`（order 8）+ Shell/PageHost 注册 + menu-leaf 契约测试 allowlist。**均 additive、core 零改动、manifest 无 diff**（155×4）。交接：vue/solid/svelte 的 flat+detail+virtual 旧守卫（vue `TableBody.ts:52` / solid `TableBody.tsx:115` / svelte `IrisTable.svelte` `useVirtual`）留待后续批。

## iris 独有（批 AG，react —— vxe 没有的内置能力）

| 能力                      | 说明                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                    |
| ------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `persistState` 状态持久化 | vxe 无内置持久化（官方做法是手动监听事件 + 本地存储）。iris 把它做成声明式：`persistState={{ storage, key, include }}` 挂载时从存储读回快照（经对应 change 回调回放：sort → onSortChange、multiSortState → onMultiSortChange、filters → onFiltersChange、filterValues → onFilterValuesChange、columnVisibility → onColumnVisibilityChange、columnOrder → onColumnOrderChange、columnWidths → onColumnWidthsChange），每次变更把**当前 props** 序列化写回。表格受控，该能力是纯 LOADS/SAVES 协调器（零新增内部状态）；`pageSize` 是文档化特例——无回调（代理 `onPageChange` 是通知），仅在 `proxyConfig.onPageChange` 存在时恢复（`onPageChange(1, restored)` 在首次 query **之前**应用，避免默认 10 的双请求），无代理则整体跳过。`storage: false` 完全禁用（不读不写）；默认键 `'iris-table-state'`；`include` 默认全部 8 块；SSR 安全（window 守卫）；恢复/保存顺序契约：恢复 effect 在保存订阅之前、逐通道 skip-first ref，挂载提交永不把恢复前的值写回存储（恢复通道保留恢复值，写幂等 + JSON 去重）。                                               |
| 可变高度虚拟化            | vxe `virtualYConfig` 的「增强模式」（可变行高）在 iris 是 `virtualScroll.itemHeight` 的函数形：`itemHeight: (index) => px`。整条管线本就支持（core `computeVirtualRange`/`buildOffsets` + `IrisVirtualScroll` offset 树），本批仅收窄类型。行按**累计偏移**定位（`translateY(cum[i])`，非 `i * h`）；函数收到的是**虚拟 plan 下标**（详情槽/树槽交错后的槽位，非 bodyData 下标——文档化陷阱，也允许应用显式给详情槽定高）；固定数字形不变（闭式窗口 + `i * h` 定位）。                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                   |
| 命名视图 `views`          | vxe 无等价物（官方做法是手动监听 + 存储）。iris 把它做成声明式：`views={{ storage, key, label, activeKey }}` 工具栏渲染一个紧凑 select（`data-iris-table-views`）列出已保存快照 + 「＋ 保存」项（展开内联输入 `data-iris-views-save`，Enter 确认 / Escape 关闭）+ 活动视图的删除（×，`data-iris-table-views-delete`）。快照 = 与 `persistState` **同一个收集器**（同样的 8 块 + 逐回调门控）；应用 = 同一套逐块回调（`pageSize` 特例：视图应用复现挂载恢复序列 `onPageChange(1, size)` + 恰好一次 request）。挂载加载与 `persistState` 同守卫（window/JSON 损坏/`storage: false`）；同名 upsert；`activeKey` 受控-only（`views.activeKey` + `onActiveViewChange`，不持久化）；存储键 `'iris-table-views'`。**批 AJ：**快照收集器在 `views` 在场时另捕获受控 `query` 字符串（`IrisTablePersistedState` 增 `query?: string`；`persistState` 保存循环只遍历 `IrisTablePersistPiece`，故其路径字节不变）；应用时 query **先于**其他块经 `onQueryChange` 恢复（typeof-string 类型守卫，篡改存储不达回调）；遗留无 `query` 的快照照常加载、不触碰当前 query。 |
| 范围浮动工具栏            | vxe 无等价物。`cellRange` 有活动范围时，一个迷你操作条浮在**首个选中单元格**上方（ContextMenu 同款虚拟锚点 = 该单元格的活 rect、placement top、flip/shift 开、portal；与右键菜单的两处有意分歧：`autoUpdate` 滚动时重定位而非关闭、无关闭按钮——可见性源自范围 store，`clearRange` 即隐藏）。三个动作 1:1 复用既有路径：复制 → 当前范围的 TSV（clipConfig 同款 `buildRangeTsv` + `writeClipboardText`）；导出 CSV → 范围矩形的**无表头** CSV（core `downloadCsv`）；清除 → 范围内每格置 `''`（pasteIntoRange 同款 byKey patch + 一次 `commitRowList`）。Esc / 外部点击（`useDismiss`）清除范围从而隐藏。批 AJ 另加 统计 按钮（见下行）。                                                                                                                                                                                                                                                                                                                                                                                                                 |
| 范围统计 `rangeStats`     | vxe 无等价物（最接近是 Excel 状态栏）。浮动条在 清除 之后新增 统计 按钮（`data-iris-range-stats`）：点开一个小面板（`data-iris-range-stats-panel`）渲染在浮动条容器内、**绝对定位其下方**，按列列出所选矩形（anchor→active 归一化，行/列双向含端点）内 计数/求和/平均/最小/最大。数值语义与 core `aggregate` 完全一致：`count` = 非空单元格、sum/avg/min/max 仅取 `Number` 有限值（非数值忽略）；唯一分歧：无数值子集 → `null`（面板渲染 `—`，而非 `0`/`NaN`），空范围 → `{}`。面板打开态**提升到 Table**（浮动条每次范围变化 remount `key={rangeToolbarSeq}`，提升保证重算时面板保持打开）；统计 memo 依赖 `[activeRange, bodyData, leafColumns]`（bodyData = 已查询/筛选的显示行；列键走 `dataIndex ?? key` 同 `getCellValue` 间接层，core 纯于 `{ key }`）；Esc / 外部点击复用浮动条既有 `useDismiss`（清范围即隐藏 + 复位打开态）。i18n：`table.range.stats` + 面板表头 6 键（en + zh）。                                                                                                                                                           |
| 自然语言查询 `query`      | vxe 无内置查询语法。iris 把它做成声明式受控输入（`query` + `onQueryChange`，工具栏标题右侧渲染 `data-iris-table-query-input`，仅当 `query !== undefined` 时出现）：core `parseTableQuery` 解析 `field op value` 语法（`= != > >= < <= contains in`、单/双引号值、`in (a, b, c)` 列表、尾部 `sort by field asc                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                           | desc`、字段名大小写不敏感、未知字段（传 `fields` 时）返回错误字符串而非抛出）。合并语义：`=`/`contains`→ 子串通道（与`filters` 同语义）、`in`→`filterValues`通道（OR-match）、关系算子 → core`matchesRule`的 typed-rules AND 通道；同字段`=`/`in`的 OR 折叠进`inValues`，同字段 `contains`/关系 OR 无法表达 → 解析错误（fail-closed），跨字段 OR 归一为 AND。`sort by` 仅在所有 sort prop（`sort`/`defaultSort`/`multiSort`/`multiSortState`/`defaultMultiSort`）都缺席时播种排序，用户任何排序交互立即接管。解析错误显示 muted `data-iris-query-error` 提示并**保留最后一次有效解析**（ref 模式）继续过滤。代理模式：子串/in 通道逗号合入远端 filter map（首请求即携带，`remoteFilter` 变更经 effect 推送），关系 rules 无文本序列化保持本地-only（文档化）。i18n：`table.queryPlaceholder`（en + zh「自然语言筛选，如 age > 25 and role = Test」）。 |

| 范围粘贴（选区矩形填充） | vxe 的粘贴是流式（锚点起逐格继续）；iris 批 AK 对**多格选区**改为 Excel 式**矩形精确填充**：剪贴板 TSV 从选区左上角起逐格写入，只填选区矩形本身——剪贴板小于选区 → 左上角填充、其余格保持不变；大于选区 → 裁到矩形（超出表格末行/末列同样忽略）。单格选区保持批 O 的流式行为（锚点继续），既有粘贴测试不变。两种路径都走同一个 byKey patch map + **一次 `commitRowList`**，值保持字符串。 |
| `editRules.unique` 唯一性规则 | vxe 无内置唯一性校验（需 validator 手写）。iris 批 AK 在 core `EditRule` 增加 `unique?: boolean` 内建规则：对同列做 **String 比较**（跨类型如 `1` vs `'1'` 视为重复），空值两侧豁免，编辑行自身按**引用身份**跳过（改成原值不误报）；失败消息 = 规则的 `message` 或英文默认 `'Value must be unique'`（与现有 required/pattern 等默认消息同风格）。数据上下文经 `validateEditRules`/`validateEditRulesAsync` 的**可选第 5 参** `context?: EditRuleContext<Row> { rows, columnKey }` 传入（新增**具名导出接口** `EditRuleContext`）；无 context（或无 rows/columnKey）时该规则跳过（no-op 通过），旧调用方字节兼容。react 表在 cell/row 两种编辑模式的校验桥均传入 `{ rows: externalDataRef.current, columnKey: 列 key }`（引用跳过依赖同一批行对象）；vue/solid/svelte 适配器尚未接线——同列唯一性在该三端暂为 no-op（文档化缺口）。 |
| 内置撤销/重做 `undo` | vxe 无内置 undoRedoHistory（官方示例手写快照）。iris 把它做成声明式：`undo` 布尔 prop（默认 off）开启后**每条数据变更**（行操作 insertRow/removeRow(s)/updateRow/loadData、粘贴、find&replace、范围清除、cell/row 编辑、批编辑）都把**变更后**的行列表压入 core `createUndoStack`（`maxHistory: 100` + 初始快照 + 内容相等跳过死步骤）——**两个变更漏斗都接线**（`commitRowList` 与 `commitValue`，后者直写 `setLiveData` 从不经过前者，漏掉它 undo 会静默错过每一次内联编辑；基线措辞为「push 变更前」与 core 的 redo 语义矛盾——redo() 返回的是变更后的快照，故实际 push 变更后，否则二次变更后 Ctrl+Y 无法重放，测试明确覆盖）。Ctrl/Cmd+Z 撤销、Ctrl/Cmd+Y（或 Ctrl/Cmd+Shift+Z）重做：window 监听、仅根容器内目标、跳过 INPUT/TEXTAREA/SELECT/编辑器、**编辑会话打开时不劫持**（编辑器自己的 Ctrl+Z 优先）；重放经 `restoringRef` 守卫走 `commitRowList`（setLiveData + onDataChange）**不重推**。工具栏标题右侧 ↶/↷ 按钮（`data-iris-table-undo`/`data-iris-table-redo`），disabled 由 `canUndo()/canRedo()` 实时驱动（栈非 observable store——每次 push/undo/redo bump tick 重渲染重读）。恢复后消失的选择键被修剪（`selModel.set` 过滤，同 removeRows 模式），保留键保持选中。外部重喂数据只在栈未触碰时重建基线（交互作用域，vxe parity）。i18n：`table.undo`/`table.redo`（en + zh）。 |
| 批量编辑面板 `toolbar.batch.edit` | vxe 无内置批量填值（需手写循环 + 重渲染）。iris 把既有批量按钮变成内置面板：`toolbar.batch.edit: true` 时点批量按钮（multi + 选中 ≥ 1）展开工具栏锚定面板（`data-iris-batch-edit-panel`，右对齐下拉、Esc/外部 pointer-down 关闭、再点按钮切换）：**可编辑列**下拉（`data-iris-batch-edit-column`，只列 `c.editable` —— 与内联编辑同一门控）+ 值输入（`data-iris-batch-edit-value`）+ 应用按钮（`data-iris-batch-edit-apply`，`table.batchEdit.apply`）。应用 = **一次 `commitRowList`**：每个选中行的目标列置为输入值（按 `rowKey` 字段寻址，值保持字符串、editRules 不重验——粘贴 parity），选择不变，恰好一次 `onDataChange`；该变更同样进入 undo 栈（可与 Ctrl+Z 联动）。`edit: false`/缺省时批量按钮行为字节不变（外部 `onClick`）。i18n：`table.batchEdit.column`/`table.batchEdit.apply`（en + zh）。 |

## vxe-grid 功能清单（VxeTableProps + VxeGridProps）

### 1. 编辑（editConfig / editRules / validConfig）

- **editConfig**：`trigger: 'click'|'dblclick'|'manual'`、`mode: 'cell'|'row'`、
  `autoFocus`、`autoClear`（切格自动清未提交）、`showStatus`（updated/inserted 状态图标）、
  `showAsterisk`（必填星号）、`showUpdateStatus`、`cache`
- **editRules**（列级规则集）：`required` / `min` / `max` / `type: number|string|array` /
  `pattern`（正则）/ `validator`（同步|异步）/ `message` / `trigger: blur|change|manual`
- **validConfig**：校验模式（type: 'one'|'all'、错误提示位置）、`showMessage`（false 时仍阻断提交 + 保留 aria-invalid，仅隐藏错误文案，批 F ✓ react）
- **undoRedoHistoryConfig**：编辑撤销/重做（core 已有 undo 可组合）

### 2. 选择

- checkboxConfig：多选（reserve 跨页保留、range 框选、checkMethod、showHeader）
- radioConfig：单选（row、checkMethod）
- 选择方法（批 F ✓ react）：`selectAll`（全选，遵守 checkMethod）/ `toggleRowSelection`（单行切换，绕过 checkMethod）/ `clearSelection`（清空）

### 3. 滚动 / 虚拟

- scrollX / scrollY（固定高度滚动）、**virtualXConfig / virtualYConfig**（虚拟滚动，
  含增强模式 vs 固定行高）

### 4. 列能力

- resizableConfig（列宽拖拽，minWidth/maxWidth）、columnDragConfig（列拖拽排序）、
  columnConfig（visible/fixed/formatter/width 等）、visibleMethod（列可见谓词，批 U ✓ react）、seqConfig（序号列）、
  mergeCells / spanMethod（合并单元格）、mergeHeaderCells（表头合并，批 P ✓ react）、
  customConfig（列自定义面板：搜索/拖拽排序/可见性切换/重置，批 S ✓ react）

### 5. 行能力

- rowConfig（keyField/isHover/useKey）、rowDragConfig（行拖拽排序）、
  expandConfig（展开行；`expandAll` 一次性全展开，批 F ✓ react）、rowGroupConfig（行分组）

### 6. 排序 / 筛选

- sortConfig（多列、remote、sortMethod）、filterConfig（本地/远程筛选、
  resetMethod、筛选类型）、floatingFilterConfig（浮动筛选）
- multiSort（批 F ✓ react）：`multiSort` 多列排序（点击追加/原地升→降/移除，chronological 点击序，
  非主排序列序号徽标，链式稳定比较器，代理发 `sorts` 数组）

### 7. 数据代理（proxyConfig）

- query/insert/remove/save ajax 代理、响应解析、表单联动

### 8. 工具栏 / 表单 / 缩放

- toolbarConfig（内置按钮：refresh/import/export/zoom/custom）、formConfig（搜索表单）、
  zoomConfig（全屏）、layouts

### 9. 导入导出 / 打印

- exportConfig（csv/xls/xlsx/html/pdf）、importConfig（文件导入）、printConfig（打印）

### 10. 交互增强

- mouseConfig（鼠标选中/框选）、areaConfig（区域复制）、keyboardConfig（键盘导航）、
  fnrConfig（查找替换，批 O ✓ react）、menuConfig（右键菜单）、clipConfig（批 O ✓ react）、tooltipConfig（单元格，批 G ✓ react；表头/表尾提示，批 P ✓ react）、emptyText、
  loadingConfig、footerMethod（汇总）、currentRowConfig
