### 🔴 发现 S1（关键） — 任意 HTML 注入通过自定义 Markdown 清理器

| 字段     | 值                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                        |
| -------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 类别     | **输入验证 / XSS**                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                        |
| 严重性   | **严重**                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                  |
| 标题     | 自定义 Markdown — HTML 转换器中的正则表达式清理存在 XSS 绕过漏洞                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                          |
| 位置     | `packages/plugin-markdown/src/core/index.ts:25-68`（清理函数）、`:181-198`（渲染器使用 `dangerouslySetInnerHTML`/`innerHTML`/`{@html}`）                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                  |
| 描述     | Iris UI 自带一个无外部依赖的自定义 markdown 解析器。它实现了一个正则表达式清理器，用于移除 `<script>` 标签、`javascript:` 链接、事件处理器、data: URL、`<iframe>` 和 `<style>` 标签。清理结果随后通过 React 的 `dangerouslySetInnerHTML`、Vue 的 `innerHTML`、Solid 的 `innerHTML` 以及 Svelte 的 `{@html}` 注入到 DOM 中。该正则表达式方法存在多个已知的绕过向量。                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                       |
| 攻击场景 | 一个用户可控的 markdown 输入（例如在 CMS 或其他用户生成内容上下文中使用 `IrisMarkdown`）可能通过以下方式绕过清理器：<br><br>**1. 无引号的事件处理器（最主要的绕过后门）：** `<img src=x onerror=alert(1)>` — `stripEventHandlers` 的正则表达式 `/\s+on\w+\s*=\s*(['"])[\s\S]*?\1/gi` 在 `=` 后**要求**存在引号。没有引号的 HTML 属性则会被完全跳过。<br><br>**2. 嵌套的 `<script>` 标签：** `<script><script>alert(1)</script></script>` — 非贪婪匹配 `[\s\S]*?` 在第一个闭合的 `</script>` 处停止，留下 `</script>` 作为未闭合的孤立文本，可能扰乱解析器。<br><br>**3. HTML 实体的 `javascript:` 编码：** `<a href="&#106;avascript:alert(1)">click</a>` — 清理器匹配的是字面文本 `javascript:`，而不是 HTML 实体解码后的版本。<br><br>**4. SVG 命名空间事件：** `<svg><animate onbegin=alert(1) attributeName=x dur=1s>` — `stripEventHandlers` 的正则表达式会匹配 `onbegin=...`，但要求存在引号；在 SVG 中的无引号属性同样会被此绕过。 |
| 影响     | 受影响上下文中（配置编辑、通知正文、任何用户可提供 markdown 的位置）的存储型跨站脚本攻击（XSS）。攻击者可以窃取 cookie、冒充用户、执行 API 调用，或篡改页面内容。                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                         |
| 建议     | **短期方案：** 用经过实战检验的 HTML 清理器替换正则表达式清理器。`DOMPurify`（经安全审计且被广泛使用）应当集成进来作为依赖：<br><br>`ts<br>import DOMPurify from 'dompurify'<br><br>export function markdownToHtml(md: string): string {<br>  // ... 解析 markdown 为 HTML ...<br>  return DOMPurify.sanitize(html)<br>}<br>`<br><br>**长期方案：** 考虑迁移至成熟的、经过安全审查的 markdown 渲染器（如 `marked` + `DOMPurify`，或 `rehype-sanitize`），而不是维护自定义的 markdown 实现。<br><br>**减轻措施（立即方案）：** 在插件文档中警示使用 `IrisMarkdown` 时，用户必须通过 `<meta>` 或 HTTP 头部设置严格的 CSP，包含 `script-src: 'none'`，以防止即使清理失败时 XSS 被利用。                                                                                                                                                                                                                                                      |
| 工作量   | **M**（1-2 天集成 DOMPurify，包含测试 + 跨框架验证）                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                      |

## 3. STRIDE 分析

| 威胁                                   | 状态                | 分析                                                                                                                                                             |
| -------------------------------------- | ------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **S**poofing（身份伪造）               | ✅ **不适用**       | 客户端组件库。身份伪造由宿主应用和认证基础设施处理。                                                                                                             |
| **T**ampering（篡改）                  | ⚠️ **存在链式风险** | 通过 S2（皮肤值注入）进行的 CSS 篡改可能被用于视觉操纵。数据原本存储在内存中，且通过不可变更新来防范篡改。                                                       |
| **R**epudiation（抵赖）                | ✅ **不适用**       | 无审计日志或事务系统。由宿主应用处理。                                                                                                                           |
| **I**nformation Disclosure（信息泄露） | ⚠️ **存在链式风险** | 通过 S1（XSS）的信息泄露是首要风险。通过皮肤 token 的 CSS 数据渗漏是一种间接路径。主题/skin 持久化仅包含非敏感的皮肤 ID。                                        |

## 6. 最终总结

| 维度                        | 状态                                                                                                                                                                                                                                                                                                                       |
| --------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **整体安全态势**            | ⚠️ **存在一个严重漏洞，基础尚可**                                                                                                                                                                                                                                                                                          |
| **强项**                    | 核心零依赖、安全的 store 实现（无原形污染）、安全的 `IrisIcon`（结构化 SVG 而非 innerHTML）、CSS 随机数支持、所有核心组件的 aXe 无障碍测试、纯函数式数据流（不可变性进一步降低了篡改风险）                                                                                                                                 |
| **关键弱点**                | **自定义 markdown → HTML 转换器（plugin-markdown）** 使用了存在已知 XSS 绕过模式的正则表达式清理器，并在所有四个框架适配器中通过 `dangerouslySetInnerHTML`/`innerHTML`/`{@html}` 渲染其输出                                                                                                                                |
| **最大风险**                | 在 IrisMarkdown 组件中呈现用户提供内容的 CMS 或任何 UI —— 会受到存储型 XSS 攻击                                                                                                                                                                                                                                            |
| **最重大的 3 个问题**       | 1. S1：Markdown 清理器允许通过无引号事件处理器实现 XSS<br>2. S2：皮肤系统写入未经清洗的 CSS 变量值<br>3. S3：CSP 建议未作为安全基线强制要求                                                                                                                                                                                |
| **最重大的 3 个快速制胜点** | 1. 集成 DOMPurify 作为 markdown 管线的防线（修复 S1，低成本高价值）<br>2. 为 CSS 变量值添加白名单验证模式（S2，约 10 行代码）<br>3. 为 IrisProvider 文档添加 CSP 章节（S3，约 30 分钟）                                                                                                                                    |
| **安全债务**                | 自定义 markdown 解析器/清理器是安全债务的主要来源——没有一个独立的安全审计能够验证其抗注入能力。建议要么（a）集成经过实战检验的库（`marked` + `DOMPurify`），要么（b）聘请一名安全专家对该解析器进行专门审查。markdown 的每个新功能（表格、HTML 块、任务列表等）都会扩大攻击面，而自定义实现每次都需要对 XSS 绕过进行审查。 |

### 需修复后的重新评估

一旦 S1 通过集成 DOMPurify 得到修复、S2 通过值清洗得到处理、S3 通过文档得到解决，此项目的安全态势将升级为 **“优秀”**。现有的约束——零核心依赖、不可变状态、结构化组件 API——在安全坚固性方面已经优于该类别中 95% 的项目。核心存在**一个**安全缺陷（markdown 插件），它不必要地削弱了其他方面出色的安全态势。
