## 核心结论

### 事实核查的独立验证

我在执行分析前独立验证了原始文档的每个事实：

| 方向           | 裁决                  | 关键发现                                                                                                               |
| -------------- | --------------------- | ---------------------------------------------------------------------------------------------------------------------- |
| ① 数据导入     | ✅ 准确               | `toCsv`/`toSpreadsheetXml`/`toJson`/`toHtml` 四导出存在，零导入对应                                                    |
| ② 跨应用数据   | ✅ 准确               | 剪贴板仅 `copyText(text: string)`，无应用间通信                                                                        |
| ③ 路由适配器   | ❌ **事实严重错误**   | `cms-vue` **不存在**；4 个 CMS 都**没有**用外部路由库（React 用 47 行自定义 hash router，其余靠 AdminLayout 内部 Tab） |
| ④ 优雅降级     | ⚠️ 概念有效但虚构代码 | `errorRetryCount` 在 `DataSourceState` 中**完全不存在**（逐行验证 `types.ts:33-54`——零匹配）                           |
| ⑤ 运行时元数据 | ✅ 准确               | 构建时 manifest 完整，运行时完全缺失                                                                                   |

### 任务分解产出

**17 个任务**，每任务 3-4h，分 5 个完全可并行的方向组：

- **组 A**（方向①）：4 任务串行（TASK-001 fromCsv → TASK-002 fromJson/XML → TASK-003 插件协议 → TASK-004 四框架桥）
- **组 B**（方向②）：3 任务（TASK-005 类型协议 → TASK-006 剪贴板 / TASK-007 InterAppBus 并行）
- **组 C**（方向③ 修正后）：3 任务串行（TASK-008 RouterAdapter 接口 → TASK-009 四桥 → TASK-010 AdminLayout 集成）
- **组 D**（方向④ 修正后）：3 任务串行（TASK-011 createRetryable → TASK-012 集成 → TASK-013 组件降级）
- **组 E**（方向⑤）：4 任务（TASK-014 注册表 → TASK-015 校验器 + TASK-016 useComponentMeta 桥并行 → TASK-017 DevTools）

### 关键风险

1. **🔴 方向三事实错误**—利益相关者信任受损，需 Day 1 勘误 + scope 重新确认会议
2. **🔴 方向四 `errorRetryCount` 虚构**—需在文档开头标注 errata
3. **🟡 CSV 编码检测**（方向①）—GBK/Big5 可靠检测困难，用 `detect-character-encoding` 缓解
4. **🟡 写操作重试重复提交**（方向④）—默认关闭，仅在有 `idempotencyKey` 时启用
