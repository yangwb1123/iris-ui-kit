| **Title**           | `JSON.stringify` in `saveSnapshot` crashes on circular references — crashes all mutation operations                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                        |
| **Location**        | `packages/core/src/form.ts:269` (`saveSnapshot`)                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                           |
| **Description**     | `saveSnapshot` calls `JSON.stringify(store.getState().values)` with no try/catch. The uncaught TypeError propagates up through `setFieldValue`, `setValues`, `arrayPush`, `arrayInsert`, `arrayRemove`, `arraySwap`, and `arrayMove` — all mutation operations that call `saveSnapshot()`. This is called _after_ `store.setState` has already applied the state change, so the data is corrupted in the store but the snapshot fails — leaving the undo history inconsistent with the current state. |
| **Attack Scenario** | 1. The uncaught exception propagates to the caller, crashing the UI event handler.<br>4. Meanwhile, the store now has the circular value, but undo history is empty or inconsistent.                                                                                                                                                                                                                                                                          |
| **Impact**          | Crashes UI on any form mutation with circular data. Undo history becomes inconsistent with form state.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                     |
| **Recommendation**  | Wrap `JSON.stringify` in try/catch. On failure (circular reference), either skip the snapshot or use a custom serializer that handles circular references (e.g., `JSON.stringify` with a replacer that marks circular refs as `'[Circular]'`).                                                                                                                                                                                                                                                                                                                                                                                                                             |
| **Effort**          | S (< 1 day)                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                |

```ts
const saveSnapshot = (): void => {
  if (maxHistory <= 0) return
  history.splice(historyIdx + 1)
  try {
    const snapshot = JSON.stringify(store.getState().values)
    if (history.length > 0 && history[history.length - 1] === snapshot) return
    history.push(snapshot)
    if (history.length > maxHistory) history.shift()
    historyIdx = history.length - 1
  } catch {
    // Value contains non-serializable data (circular ref, BigInt, etc.)
    // Skip snapshot — undo/redo unavailable for this mutation
  }
}
```

### Top 3 Critical Issues

1. **🔴 Validator exceptions cause unrecoverable DoS** (Finding 1) — A single throwing validator leaves `validating[name] = true` or `isValidating = true` forever. Three call paths affected: `validateOnMount`, `scheduleValidate`, and `handleSubmit`. Fix: wrap validator execution in try/catch, use `Promise.allSettled` everywhere.

2. **🔴 Missing double-submit guard** (Finding 3) — No early return in `handleSubmit` when `isSubmitting` is already true. Concurrent submissions can cause duplicate orders/payments. Fix: one-line guard at top of `handleSubmit`.

3. **🟡 `Promise.all` vs `Promise.allSettled` inconsistency** (Finding 2/8) — Form store uses `Promise.all` which fails fast on any validator rejection. Standalone engine uses `Promise.allSettled`. The form store is strictly less robust. Fix: two `s/\.all/.allSettled/` replacements.

### Top 3 Quick Wins

1. **Add try/catch around validator execution** (Finding 1, ~20 lines, S effort) — Prevents complete form DoS. The single highest-impact change.

2. **Replace `Promise.all` with `Promise.allSettled`** in form store's `validateForm` and `validateStep` (Finding 2/8, ~4 lines, S effort) — Aligns with standalone engine and prevents total validation failure.

3. **Add early-return guard in `handleSubmit`** (Finding 3, ~1 line, S effort) — Prevents concurrent submissions and duplicate orders.

### Recommendation

**Do not ship as-is.** The three critical/high-severity findings (Findings 1, 2, 3) represent real, exploitable denial-of-service vectors that would manifest in production. A single validator that throws on unexpected input — a common scenario with weakly-typed validators accessing nested properties — permanently freezes the form. The `Promise.all` vs `Promise.allSettled` inconsistency means the form store is objectively less robust than the standalone engine it re-exports.

The estimated fix effort for all P0-P1 findings is approximately **2-3 hours** (4 S-effort changes, each under 50 lines). Once addressed, the security posture moves to **Good** ✅.
