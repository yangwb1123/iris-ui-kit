- **iter 24** — fix(solid): `IrisPagination` in **uncontrolled mode never moved `aria-current`** when a page button was clicked — the page state advanced but the displayed active page froze on the initial one. Root cause: page buttons render inside `<For each={items()}>`, which only re-runs its callback when an item's _identity_ changes; `getPageRange` returns the same page-number primitives when only the current page moves, so the `active: item === current()` boolean (evaluated at map-callback time) never re-evaluated. Fix: make `active` a **thunk** (`() => item === current()`) bound reactively in the button — the same pattern the component already used for `label` (whose comment flagged exactly this "For's map callback is untracked" gotcha) but had missed for `active`. Found by the new pagination behavioral contract (iter-25); the existing unit test missed it because it asserted aria-current only in _controlled_ mode. +1 targeted unit regression test (uncontrolled click moves aria-current). 126/126 gates green.
