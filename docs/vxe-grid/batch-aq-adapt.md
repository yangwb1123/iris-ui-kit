- **jsdom quirks**: no `PointerEvent`/`document.elementFromPoint`/`setPointerCapture` — tests dispatch plain `Event`s with pointer fields inside `act` (the vxe-parity rowDrag pattern) and stub `elementFromPoint`; `setPointerCapture` is guarded by `?.` + try/catch.
- **Drag up/left semantics**: the rectangle only grows DOWN/RIGHT from the range edge (`max(pointer, range.end)` + table-bounds clamp) — a pointer inside the range or above/left of its end yields no target cells and a no-op release (documented in the prop JSDoc + comparison doc).
- **Known simplifications (documented)**: hit-testing via `elementFromPoint` resolves to rendered cells only (virtual-scroll off-screen rows are unreachable — the fill covers the visible body, same as Excel dragging past the viewport edge); Escape mid-drag clears the range like any Escape (no drag-specific cancel key); the aria-label is omitted (non-focusable pointer-only affordance — axe-safe as a plain span).
