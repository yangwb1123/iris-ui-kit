**Design decisions (per the task's "pick the framework-neutral approach and document"):**

- **Framework-neutral shape**: the factory's constraint `ColumnPresetDescriptor` is a minimal partial descriptor `{ formatter?, align?, editor?, editRules? }`; `formatter` is typed `unknown` because strictFunctionTypes makes a fixed-arity function type incompatible with adapter formatters of different arity (react's `(value, row) => ReactNode`) — the preset FILLS a `(value) => string` helper and the generic `C` return carries the adapter's own column type back with zero casts (documented in the core file).
- **User fields win**: the merge fills ONLY fields the column leaves `undefined`; `align: undefined` cannot kill the preset default. Adapter applies via one memo, reference-preserving for zero-preset tables (byte-identical with the pre-preset render path).
- **Shortcuts need keyboardNavigation**: `focusedCell` state only exists under keyboardNavigation's roving cell focus (cells get `data-grid-row`/onFocus there); without it the shortcuts are inert (documented in props.ts + docs). While an inline editor is open the editor's own keys win (`editing === null` gate, both cell-mode `editTarget.editing` and row-mode `rowEditing`); the event TARGET must be a grid cell so header focus never triggers on a stale `focusedCell`. Delete/Backspace writes `''` (not `null` — `clearActiveRange`/draft-seeding parity; `null` would flip cell type on number editors), `onCellEdit` not fired (paste/batch-edit/range-clear parity), undo covered free via the `commitRowList` funnel.
