## 4. 测试策略评估

### 测试金字塔

```
         ❌ E2E（缺失）
         ⚠️ 集成（合约测试仅涵盖跨框架，无组件组合）
    ✅ 单元测试（8,500+ 行跨 500+ 文件）
   ✅ 静态分析（TypeScript、ESLint、架构检查）
```

**评估：** 金字塔很好地向上倾斜，但缺少顶部的两层。没有 E2E 测试和最小的集成测试意味着真正的用户流程无法通过自动化验证。

### 测试分类

- ✅ **正确性测试**：主要焦点——每个功能单元都有期望边界情况
- ✅ **回归测试**：合约覆盖和密度测试确保新场景不会破坏旧场景
- ✅ **规模测试**：100k 行正确性（`scale.test.ts`）
- ⚠️ **性能测试**：存在但建议性（`bench` 带有 `continue-on-error: true`）
- ❌ **安全测试**：完全缺失
- ❌ **混沌测试**：完全缺失
- ❌ **视觉回归**：完全缺失

## 5. 最终总结

### 总体测试健康度：**良好** ⚠️（接近优秀）

**测试基础设施优势：**

- 跨 4 个框架的 500+ 个测试文件中的 **9,841 次断言**
- **15 道 CI 质量门**，带有棘轮式架构检查
- **42 个合约场景**，所有 4 个框架对其运行（合约覆盖率验证）
- 确定性测试模式（`fakeScheduler()`，`vi.useFakeTimers`）——**所有已知的基于时间的测试都使用假定时器**
- 跨框架对等性得到强制执行——一个框架不能比其他框架更少测试
- 防御性编码测试（null/undefined 守卫检查）
- 100k 行规模正确性测试
- 所有 4 个框架的可访问性测试

### 关键测试缺口（在生产前必须修复）

1.  **🔴 无 E2E 测试**：没有 Playwright/Cypress。jsdom 不能替代真实的浏览器。添加 5 个关键用户流程（登录、CRUD 列表、表单提交、对话框流程、主题切换）的 E2E smoke 测试。
2.  **🔴 无安全测试**：XSS、注入和输入清理未经测试。为 Markdown/HTML 渲染、URL 处理和用户提供的字符串添加测试。
3.  **🔴 无集成测试**：组件组合（表单 + 字段 + 工具提示、表格 + 分页 + 选择）未经测试。添加 10 个核心组合测试。
4.  **🔴 潜在的脆弱测试**：3 个测试文件（`Behaviors.test.tsx`、`long-press.test.ts`、`auto-dismiss.test.ts`）在没有假定时器的情况下使用实时计时器。

### 高优先级缺口

5.  **🟠 Solid/Svelte SSR 测试**：缺失。复制 React 的 `ssr.test.tsx` 模式以捕获服务器端渲染回归问题。
6.  **🟠 Solid/Svelte 断言差距**：~900 次断言相比 React/Vue 缺失。提升测试密度。
7.  **🟠 无心跳/代码覆盖率门槛**：当前覆盖率报告仅检查行数，不检查实际覆盖范围。添加 Istanbul 门槛。
8.  **🟠 性能门槛是建议性的**：基准测试使用 `continue-on-error: true`。为关键路径添加严格的门槛。

### 测试策略改进

1.  **采用 PLAYWRIGHT 进行 E2E 测试**：
    - 为每个 `apps/playground-*` 项目添加 1 个 `e2e/` 目录
    - 为烟雾测试、关键用户流程和跨框架截图测试提供 3 个测试文件
    - 将其作为 CI 中的必需门

2.  **添加安全测试层**：
    - 为包含 `innerHTML`、`dangerouslySetInnerHTML` 或未转义用户内容的组件创建专用安全测试
    - 添加用于检查 XSS 向量的 lint 规则
    - 为 `IrisMarkdown`、`IrisCommandPalette` 和用户输入字段测试清理

3.  **执行测试密度对等性**：
    - 扩展 `test-coverage-report.mjs` 以按组件跨框架比较断言计数
    - 添加 CI 检查，确保任何框架的断言密度不超过最厚框架的 20%
    - 使覆盖率报告在 CI 中具有阻塞性（不仅仅用于信息）

4.  **添加突变测试**：
    - 从核心控制器单元测试的 Stryker 集成开始
    - 目标是 >80% 的突变分数，用于关键的逻辑位（`data-view.test.ts`、`machine.test.ts`、`selection.test.ts`、`form.test.ts`）
    - 这确保测试实际上在断言正确的行为
